# 共享轨迹输出与持续采集

## 部署配置

`VLN_RESOURCE_ROOT/runs` 是采集输出根目录。2026-09-28 的开发部署设置为
`/home/beta/.local/share/vln-pipeline/runs`；`.env` 仍不提交 Git。
源数据仍用 `VLN_SOURCE_ROOT`，数据库、Redis、索引及端口保持各部署独立。
不要仅为了共享文件而让两个版本同时写同一个任务数据库。

`VLN_SHARED_RUN_PERMISSIONS=true` 明确允许本机其他用户读写采集文件。
运维需给 runs 目录设置访问 ACL 和默认 ACL，并仅给父目录补充必要的穿越权限；
不要递归开放整个 home。原子写入的运行 JSON 和导出库产生的私有权限文件会在
`workers/output_storage.py` 中针对 runs 范围放宽，运行库、凭据、数据库不受影响。
这是受信任的多人工作站配置，不是互联网文件服务的权限方案。

当前部署保留至少 30 GiB 空间，每批开始前还要求完整满足该批次的保守峰值预算。
磁盘不足时保留计划并等待处理，不删除旧数据、不无限重试失败批次。

环境验收输出放在 `runs/_validation/`；Atlas 视频缓存可使用指向
`runs/_catalog/<deployment>` 的专用链接。每个任务仍使用独立 UUID 子目录。
迁移时先复制、逐文件 SHA256 验证，再移除旧副本并保留旧路径的兼容链接。
历史命令、哈希和来源说明不做字符串替换；Artifact 路径更新，ID 保持不变。

## 网页操作

“采集数量”只包含两个选项：

- **自定义**：输入 1、8、32 或 1–1000 的其他数量，选择单台设备后提交一个有限任务。
- **持续采集**：忽略数量输入，按所选数据集、划分、角色、语言和可选 ID 范围领取未完成轨迹。

GPU0 支持 R2R、RxR、ScaleVLN；PRO6000/B200 使用各自已验收的数据集。
ScaleVLN 仍仅支持本机，不能因新增数量模式而绕过云端 HM3D 部署验收。
持续采集时 GPU0、PRO6000、B200 可以在同一计划里任意组合勾选，各自领取不重叠批次。
只选本机使用 `execution=local`，只选云池使用 `cloud_idle`，同时选中使用 `mixed`；
每个实际批次仍明确落到本机或一个具体云池，不会把一个批次广播给所有设备。
设备尚未验收时，自定义任务不能启动；已启用的云设备可先保存持续计划等待就绪。
某台设备忙碌或等待环境/容量时，不阻塞其他就绪设备。自定义数量仍是单设备有限任务；
勾选多设备后应明确选择“持续采集”，界面不会擅自把有限采集改成无限采集。

GPU0 计划由 `workers/tasks.py:reconcile` 调用 `workers/local_collection.py` 补充批次：

1. 从目录读取完整范围，排除已经校验成功、已领取及正在执行的轨迹。
2. 多个本机计划按最近领取批次时间轮转，每次只允许一个本机批次处于待执行/执行状态。
3. 检查 GPU 状态；未知或被占用时不派发，不结束他人的进程。
4. ScaleVLN 只领取场景和 NavMesh 已就绪的轨迹；后续安装的场景会自动进入候选。
5. 执行容量和环境预检，事务写入 Run、CollectionBatch、CollectionClaim，再交给原 Worker。
6. 保留原有回放、标签、LeRobot、独立验收、预览和目录登记流程。

本机 feeder 和云端 feeder 都按计划的 `compute_pools` 判断是否参与。
共用非阻塞 `collection-allocation.lock` 防止同时使用过期的容量/进度快照，
数据库 `CollectionClaim.source_id` 唯一约束作为跨计划和重启后的去重保障。
设备错误分别保存在 `progress.device_errors`，一侧更新进度不会清除另一侧的报错。
GPU0 的轮转只计算本机批次，云端补批不会推迟本机计划的公平顺序。

关闭网页后计划仍运行；暂停后不再派发，已运行的阶段按原任务边界暂停。
正在停止时不允许提前恢复，避免重复进程。失败批次需要明确点击“继续 / 重试”。
全部采完后保持 watching，等待源目录新增；不是反复生成已经完成的轨迹。

## 云端输出

云端执行中仍使用原 PFS 保存断点及租约。开启共享输出后，完成且通过独立校验的产物
由 `workers/output_storage.py:cloud_archive` 复制到共享 runs，逐文件验证 SHA256，
然后以目录重命名发布；网页引用共享副本。云端原始断点不删除。
复制在独立 I/O 线程中进行，调度器保持轮询和其他任务的租约续期；归档完成前显示
`cloud_archiving`，不会提前标记任务完成。
只归档数据、采集审计文件和阶段日志，不复制云租约、私有 env 或整个远端工作目录。
遇到同名未验收目录、符号链接或磁盘不足会报错并保留原数据，不覆盖现有任务。
